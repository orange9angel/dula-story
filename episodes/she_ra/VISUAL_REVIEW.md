# Visual Review 视觉/美学审核规范

> 本规范用于指导 AI 开发代理在每次迭代时进行**非脚本级**的视觉质量检查。
> 与 `dula-inspect-team` 的脚本级检查（角色注册、音频时长、相机角度等）互补。

---

## 审核维度

### D-V1: 角色外观细节 (Character Detail)

对每个主要角色，检查以下细节：

| 检查项 | 合格标准 | 常见问题 |
|--------|---------|---------|
| **面部特征** | 有眼睛（含瞳孔/高光）、眉毛、鼻子、嘴巴 | 缺少鼻子；眼睛像LED灯球；没有眉毛 |
| **发型/头饰** | 发型与角色设定匹配，有层次感 | 头发像头盔；颜色错误；没有层次 |
| **服装细节** | 有纹理/层次（领口、袖口、腰带、纽扣等） | 纯色平面；没有层次；颜色单调 |
| **材质对比** | 不同部位有明显颜色/亮度对比 | 全身同色；缺乏明暗对比 |
| **比例协调** | 头身比合理，四肢长度协调 | 头太大/太小；四肢过短 |

**She-Ra 角色检查清单：**
- [x] Adora: 白色短发、黑色+红色军团制服、红色肩甲
- [x] SheRa: 金色长发、白色长裙、红色披风、金色头饰
- [x] Hordak: 白色皮肤、红色眼睛、灰色装甲、黑色斗篷、尖耳朵、鼻子、胸甲、腰带、护膝
- [x] Catra: 棕色短发、猫耳、深色服装

### D-V2: 场景丰富度 (Scene Detail)

对每个场景，检查以下元素：

| 检查项 | 合格标准 | 常见问题 |
|--------|---------|---------|
| **地面细节** | 有纹理（不是纯色平面） | 纯色平面；没有阴影接收 |
| **背景层次** | 有远景/中景/近景层次 | 背景空旷；只有一堵墙 |
| **道具点缀** | 有与场景主题相关的小道具 | 完全没有道具；道具与主题无关 |
| **光影效果** | 有主光源+补光+环境光 | 单一光源；角色过暗/过曝 |
| **氛围元素** | 有粒子/雾效/天气等氛围 | 场景死寂；没有氛围感 |

**场景检查清单：**
- [x] BrightMoonScene: 城堡大厅、水晶柱、魔法光点、窗外景色
- [x] FrightZoneScene: 金属墙壁、管道、控制面板、红色警报灯、烟雾、**风暴特效（闪电+下雨+云层）**
- [x] WhisperingWoodsScene: 树木、蘑菇、小溪、雾气、萤火虫

### D-V3: 动作自然度 (Animation Quality)

| 检查项 | 合格标准 | 常见问题 |
|--------|---------|---------|
| **动作幅度** | 与情绪强度匹配 | 愤怒时动作太小；平静时动作太大 |
| **动作流畅** | 有预备-动作-缓冲的节奏 | 突然开始/停止；没有过渡 |
| **身体协调** | 四肢与躯干协调运动 | 只有手臂动，身体僵硬 |
| **表情配合** | 面部表情与台词情绪匹配 | 笑着说悲伤台词 |

### D-V4: 运镜质量 (Cinematography)

| 检查项 | 合格标准 | 常见问题 |
|--------|---------|---------|
| **景别变化** | 有远景/中景/近景/特写的变化 | 全是中景；没有特写 |
| **角度变化** | 有平视/俯视/仰视的变化 | 全是平视；角度单调 |
| **运动运镜** | 有推/拉/摇/移/跟的变化 | 全是固定镜头 |
| **角色可见** | 说话角色在画面中央，面部可见 | 角色出画；只能看到后脑勺 |
| **画面稳定** | 没有不必要的抖动 | 画面晃动；相机穿模 |

### D-V5: 光效氛围 (Lighting & Atmosphere)

| 检查项 | 合格标准 | 常见问题 |
|--------|---------|---------|
| **主光源** | 明确的主光源方向 | 光源混乱；没有主光源 |
| **角色照明** | 角色面部清晰可见 | 角色在阴影中；面部过暗 |
| **氛围光** | 有与情绪匹配的氛围光 | 紧张场景用暖光；温馨场景用冷光 |
| **阴影层次** | 有清晰的投影 | 没有阴影；阴影过重 |

### D-V6: 台词文学性 (Dialogue Quality)

| 检查项 | 合格标准 | 常见问题 |
|--------|---------|---------|
| **口语自然** | 像日常对话，不生硬 | 书面语过重；像读课文 |
| **情绪递进** | 情绪有起伏，不是平的 | 全程一个语调；没有高潮 |
| **角色个性** | 台词符合角色性格 | 反派说正派话；角色没有区分度 |
| **信息密度** | 每句台词推进剧情 | 废话太多；信息重复 |

## 审核流程

每次修改后，按以下流程执行视觉审核：

1. **运行验证截图**: `npm run verify:she_ra`
2. **逐张检查截图**: 对照上述 6 个维度检查每张 storyboard 截图
3. **记录问题**: 在下方表格记录发现的问题
4. **优先级排序**: 按 P0(必须修)/P1(建议修)/P2(可优化) 排序
5. **迭代修复**: 修复 P0 和 P1 问题后重新验证

## 与 dula-inspect-team 的关系

```
┌─────────────────────────────────────────┐
│         闭环质检体系                      │
├─────────────────────────────────────────┤
│  dula-inspect-team (脚本级)              │
│  ├── SceneInspector: 场景注册、过渡配置   │
│  ├── CharacterInspector: 角色注册、声线   │
│  ├── CameraInspector: 运镜参数、后脑勺    │
│  ├── AudioInspector: 音频存在性、时长     │
│  └── ... (共12个维度)                    │
├─────────────────────────────────────────┤
│  Visual Review (视觉/美学级)             │
│  ├── CharacterDetail: 角色外观细节        │
│  ├── SceneDetail: 场景丰富度             │
│  ├── AnimationQuality: 动作自然度         │
│  ├── Cinematography: 运镜质量             │
│  ├── LightingAtmosphere: 光效氛围        │
│  └── DialogueQuality: 台词文学性         │
└─────────────────────────────────────────┘
```

**使用方式**：
- `dula-inspect-team` 是**自动化**的，每次构建后自动运行
- `Visual Review` 是**半自动化**的，需要 AI 代理人工检查截图并记录问题

**未来演进方向**：
- 将 Visual Review 检查项固化为代码（如 `CharacterDetailInspector.js`）
- 使用 Kimi 视觉 API 自动分析截图（自动使用 kimi-cli 登录凭证）
- 建立角色/场景/运镜的评分卡（Scorecard）
