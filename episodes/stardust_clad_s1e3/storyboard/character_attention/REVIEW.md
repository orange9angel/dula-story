# 本轮实验结论

**本集未达到“整体超过上一集”的目标，更没有达到参考片的角色与表演水平。**
它是一份完整的 136 秒实验版，不作为正式认可基线。主代理直接审画面，没有把
视觉评价交给其他模型；文本审稿与视觉判断分开。

新剧情《不能等的半拍》以小凿为主视角，新增缄网与苇禾，尝试让等待、负重、
牺牲筛盘和切弦形成因果。文本审查通过，部分因果仍没有被画面清楚表达。

## 参考能比什么

继续使用用户提供的本地参考原片，按实际内容选择脸部、肩颈、眼神和受击段，
不需要用户逐张截图。在已查看的片段中，参考的优势明确：

| 维度 | 本集表现 | 对照结论 |
|---|---|---|
| 脸与肉体 | 增加鼻颊明暗、颈线、受力嘴形；面部和四肢仍有基础几何感 | 参考的眼窝、颧颊、鼻唇、颈肩关系更完整，参考胜 |
| 发型 | 去掉原型突兀翘环，加入发梢小幅运动；大形仍像帽壳 | 参考的主束、碎束、留白和轮廓变化更有设计，参考胜 |
| 微表情与眼神 | 有眨眼、视线、用力与害怕控制，但几种情绪仍很接近 | 参考的眉眼、嘴角、脸颊与头姿协同更强，参考胜 |
| 发力与反应 | 有预备、出手、拉回、负重和反击；幅度及传递仍弱 | 参考在可见受击姿势与脸部反应上明显更强 |
| 镜头与效果 | 有出场、银尘显弦、方向性拳风；大量镜头仍像固定机位展示角色 | 参考对轮廓、大小、反应与效果的组织更成熟 |
| 走路自然度 | 踝点支撑稳定，但起步蹲低、上身变化小，末步仍机械 | 参考现有走路窗口含碎石下坡，不能给平地步态作同条件排名 |
| 声画 | 加入发力人声、风、断裂和拉索音；沿用已认可配乐 | 仅完成音频技术检查，没有听觉证据，不排名 |

没有建立跨角色、跨片段校准的总分。上述结论来自具体片段，不伪装成整部作品的
客观排行榜。本集与 S1E2 的角色、场景不同，也不能把某张新头像较细等同于整集进步。
当前 S1E2 的整体造型与场面成熟度仍是更可靠的系列基线。

## 自主发现后实际改了什么

| 发现 | 修改与复看 | 仍不能据此宣称 |
|---|---|---|
| 重搭身体丢掉成熟战壳，腰部断开 | 接回系列战壳结构，补连续内搭；保留原型证据 | 衣甲和肉体关系已经自然 |
| 旧颈筒露白、披风变硬板 | 隐藏被误继承的部件，复看完整人物 | 新角色的整体设计已胜过基线 |
| 栏索挡住苇禾求救的脸 | 断索随损坏下垂，调整求救机位 | 求救表情已足够有感染力 |
| 救回后仍站在破损桥板上 | 分开前后半桥面，把获救落点移到完好后半桥面 | 救援全过程没有接触或身体缺陷 |
| 救援目标超出手臂长度 | 调整承力姿势，实际腕点间距保持设计的 5.5 厘米 | 掌指已准确抓住腕部；此项未做完整表面测量 |
| 83–88 秒沿用站立镜头高度，俯身后只剩头在画面下缘 | 改成同时看见脸、肩臂、残盘与拉人手的构图 | 躯干受力表演已达标 |
| 位移时脚随根节点滑走 | 有限落脚计划；检查实际世界踝点，保留连续动作 | 踝点稳定等于真人步态 |

R11 发梢运动曾因未设置姿势量产生 NaN，该轮判为无效；加入有限数和控制台错误
中止后重跑。R14 的宫名标记与系列设定一致。修复数量与版本号不算质量成绩。

## 没修好的重点

1. 三人的脸型、眼形、体态与表演习惯还不够鲜明，近景缺少足够的骨肉层次。
2. 关节和硬甲仍显拼装，肩甲圆帽、宽腰带与躯干关系不够自然。
3. 行走前段膝部过低，髋胸头与手臂没有形成有性格的协调；仅数字支撑通过。
4. 出拳、束缚、切弦与对手反应的动作幅度、速度变化和后果仍弱。
5. 银尘、承重索、操纵弦、换手和残盘的关系需要更明确的局部动作与镜头。
6. 推药箱、打开箱盖、敌人退向远端等剧本文字未被充分实现；不能拿文字补画面。
7. 场景下部背景拉伸，镜头节奏和材质组合仍有游戏感。

这些问题保留为未解决，不能把“主代理看出来了”当作“制作能力已经解决了”。
下一次扩做前，应先拿一条完整角色交流与主动作样板，在相同观看尺寸下超过认可
基线；继续增加局部参数而没有明确画面收益，不是有效迭代。

## 验证范围

交付视频为 H.264、1280×720、30fps，双声道 AAC 48kHz，音画各 136 秒。
逐帧执行覆盖 4080 个时刻；已有顺序/seek 检查和最终输入摘要。4 段小凿支撑窗的
实际踝点稳定，救援腕点误差单独记录；没有全网格碰撞保证。

主代理实际输入是静帧和标时顺序帧，包括最终 MP4 解码。没有正常速度视觉输入、
慢放视觉输入或音频听觉输入，相关质量仍待证据。通用 scene_tool 对此集的
Beat/Cue/Act 编译通路不适用，三项 EVT001 未伪造为通过；场景 schema、剧本和实际
viewer 输入另外验证。详见 NOTES 与 runtime_validation.json。

`r14.json` 保存每个角色 × 14 维度的观察、来源摘要、修复证据、未检查项与漏检。
它是主代理写下的本次观察，不是程序自动生成的视觉评分。

本轮对 skill 的有效反馈是：提前对照已认可基线、追踪动作造成的后续状态、
区分发现/局部修复/整片达标。它能减少用户逐项指出问题的负担；本轮没有证明
可以独立稳定地替代全部人工迭代。
