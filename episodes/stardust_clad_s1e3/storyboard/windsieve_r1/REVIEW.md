- 场景从前集同款宫殿改为风峡转运台：开放云峡、分离石台、偏置风筛、后方运药索道

- 行动目标改为护送药篮：对手准备第二根索再袭货物，主角持续牵住第一根索使其双手
  受制；药篮到达防护墙后才切索。独立文本审稿指出的“为何不提前切断”已经补写，
  文字因果复审通过。画面能否在正常速度下充分讲清，仍不能由文本评审代替。

  `../../assets/audio/music/windsieve/Windsieve_Crossing.source.json`。
  实际曲长188.4秒，本片使用前26秒；与前集音乐不同。下载文件被驱动命名为.wav，
  但ffprobe确认内容是MP3，已在来源回执更正，不冒充原生WAV。保留本集已有角色音色、
  四条对白/发力声及Seed-Audio环境音效，按本次剧情重新摆点。
- 角色恢复完整衣甲组合，保持本集银蓝与暗紫身份；增加双方反向倾身、切索后回弹

## 可见收益和未解决项

新地点与旧宫殿明显不同；药篮在后景移动，18.5–19.0秒插入镜头显示其进入防护区，
19.55秒后才切索。双方反拉时有相反倾向，断索后对手有回弹与收步。之前岩块遮腿
的问题在最终画面已消除。

主要不足仍然严重：

1. 面颊、鼻侧和下颌仍像平面符号；高领挤掉颈部，头与身体连接缺乏肉体厚度。
2. 发束等厚、整体像雕塑；眼形相似，压痛、判断和惊讶变化太小。
3. 15–18秒拉扯主要靠整体倾身与腕点移动，胸廓、肩胯、颈部和脸的力传递不足；
   衣甲下的身体仍像刚性壳。切断后的代价和手腕疼痛也太弱。
4. 风筛轮辐、后方索道与头脸重叠，背景抢夺注意力；整体仍像搭建好的游戏关卡。
   换了场景不等于场景质量超过S1E2。
5. 备用索能看见，但再袭意图的尺寸和手部表演仍不够明确。左手转为撑腕是否能被
   正常观众立即理解，没有足够证据。镜头里手指抓握细节偏小。
6. 本片只有半步与回弹收步，没有完整走路周期；未覆盖两人后脑、后颈和所有鞋底
   接触。不能作为走路自然度或全角色各面验收。

结构化巡检见 `../character_attention/windsieve_r1.json`。部分维度保留
`needs_evidence`；清单记录不是合格证。下一轮应优先制作脸—颈—肩的近景形体/
表演样板，重新设计有胸胯传力的对抗关键姿势；继续调整光泽或加特效不能解决根因。

## 技术边界与复现

`technical.json`记录780帧、23个顺序/跳转比较点通过、MP4完整解码无错，
渲染来源与音频来源摘要一致；`.story`与生成的timeline/audio_receipt一致。
腕目标最大约4.012毫米截短。落脚指标只测脚对象原点，不是鞋底网格无穿模、
人体承力合理或运动自然的证明。

```powershell
python trials/windsieve/prepare.py
node render.mjs --viewer trials/windsieve/viewer.html --audio trials/windsieve/mixed.wav --out stardust_clad_s1e3_windsieve_trial_r1.mp4 --board storyboard/windsieve_r1/render --trace storyboard/windsieve_r1/render_trace.json
```

`script.story`是时序源，场景与角色注册见该试片的bootstrap；catalog已保存。
自定义事件由该viewer显式解释，不能声称通用引擎调度器也已接入。
`render/render_build.json`保留精确依赖摘要，包括工作区已有但本次未提交的
`dula-assets/characters/bioarmor/character_look.js`修改；仅检出本轮提交不保证
重现该已有修改。音乐仅完成来源、格式和混音时序核查，尚无听觉质量结论。

结论：完成独立内容试片并留下真实缺陷；**没有达到参考水平，也未证明整体超过
上一集，不扩为整集质量基线**。此前恢复R3复制旧场景/音乐是用户指出的创作判断
错误，已写回共用制作与配乐规则，不能改写成自主发现。
