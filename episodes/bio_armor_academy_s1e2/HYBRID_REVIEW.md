## 已确认的问题

| 层级 | 证据 | 判断与处理 |
|---|---|---|
| 顶部接缝 | `RuinsDuskScene.applyHybrid`：半径70/高36的背景筒，另加半径95的渐变球；自由仰拍见下方对比 | 图片云纹在筒顶硬切到另一张渐变，球体闭合仅堵空洞；改为统一投影或完整同源全景 |
| 镜头规避 | `viewer.js: clampSky` 限制画面上沿13.5° | 常规检查避开了问题；必须额外覆盖抬头与侧拍 |
| 地面纹理拉伸 | probe 实测远景盘 UV 的 v 全为 -1.04 | 世界投影函数遗漏 X 旋转和缩放；CircleGeometry 在旋转前 z 全为0，二维纹理退化成一条采样线 |
| 光照响应 | `applyHybrid` 的通用 loader 给所有贴图设 sRGB，包括 normal | 法线必须作为线性数据；亮度派生法线也只能补细节，不代表真实高度 |
| 画面风格 | R15 最终视频总览 | 天空细节丰富、前景大块偏黑、角色浅而平；需要环境光/雾/材质细节尺度统一，单纯提高贴图分辨率不能解决 |
| 表演版本 | 两个最终 MP4 同时间点对比 | R15 未保留 R13 反击机位与接触表演；当时入口默认旧表演，R16 起已将认可分支设为默认 |
| 身体动作 | `performance.js` 中 hong_declare 的手部目标固定、仅小幅 bob；charge1/2 移动 root 却不启用 walk | 定姿和位移不能替代动作设计；需要支撑脚、重心迁移、躯干扭转和预备/缓冲 |
| 表情 | `character_details.js` 按 emotion/量化 blink 缓存脸图；连续 gaze 等由局部 fight face 提供 | 全片需要连续眼神、眉眼、嘴角与视素分层；不能仅扩大眼睛、加眉毛或加随机晃动 |

动作根因部分来自源码，版本回退来自最终视频抽帧。没有把静帧比较说成完整动态审美验收。
现有角色已经使用连续 LimbSurface 和手部关节，应复用这些能力；无需因为是程序建模就全部推倒。

## 图转三维的具体定位

新技能：`dula-skills/build-image-to-3d/SKILL.md`。

1. **天空与很远的城市**：全景/天穹；需要的是投影连续和光色一致。
2. **中景废墟与地形**：分层图像或相机投影代理；小幅运镜有效，显露区域需要补全。
3. **拳甲、碎岩、独立道具**：图转网格最适合的先行对象；清理、定尺度、接地、材质统一后复用。
4. **主角**：一致多视图 → 网格生成/建模 → 拓扑与关节修型 → 身体/手绑定 → 面部通道 → 镜头表演。

技能可组织已有生成后端，不会凭一份说明训练出新的三维生成模型。技能首版提供
流程与离线 GLB 清点脚本，已用工作区真实静态模型运行；没有安装生成模型权重、
提交收费任务或声称已生成新主角。蒙皮存在和 morph 数量不等于变形/表情质量合格。

## 当时的制作建议与后续范围

以下建议保留诊断时的决策依据。统一天空、正式表演入口、肤色/头发与步态已按后续
版本记录推进；图转网格仍是可用流程，没有在本集中生成或替换主角网格。

先固定“已认可表演＋当前造型”的正式构建入口；然后接入经过代表镜头验证的统一
天空投影、修正地面 UV 与数据贴图色彩空间，统一环境明度。角色从三个短片段推进：
叫阵对白的视线与手势、一次带支撑脚的冲锋、已有反击后的衔接。这样每轮都能区分
是造型、变形还是表演限制，避免同时换模型、镜头和动作后无法判断收益。

需要升级模型时先做拳甲或一件中景道具的图转网格，再做单个主角的正面/侧面/抬臂/
蹲下/说话样板。自然度主要由连续形体、可控绑定和有意图的表演共同决定。
