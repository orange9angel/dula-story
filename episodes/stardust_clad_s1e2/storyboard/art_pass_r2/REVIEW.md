## 实际改动

[art_pass_r2.story](../../art_pass_r2.story) 是独立试片的镜头正本，引用原集动作时点。
12 个镜头串联睁眼、解扣反应、喊招、盾沿、低姿蓄势、起身、释放、沿链跟拍、
逼近反应、命中、后仰和落地。角色为阿鏊的三张全身姿势与一张可画五官的头像，
夜刈的解扣、后仰和屈膝落地三张全身姿势。小范围动作由局部网格、真实动作数据
和二维修正曲线共同驱动；大轮廓变化切换新画。口型接原 p19 对白包络。

背景保留左侧炉体、中央门与台阶、对打空地的叙事关系，重新画了石块尺度、缺口、
台阶边缘和大块冷暖阴影。用户指出背景仍太规则后，第二次背景生成加入本地参考
的背景画法。现在可见不均匀的断面和笔触；整体仍保留正面宫殿构图，未解决任意
角度自由运镜。背景是有限视差的画板，角色和接触影是独立层。

## 三维动作到二维单帧控制

[bake_motion_to_2d.mjs](../../tools/bake_motion_to_2d.mjs) 现为共享 skill 执行器的薄入口，
由 `config/art_pass_r2_bake_adapter.mjs` 从实际原 viewer 读取每一帧的
世界关节、根位置、相机投影及可用的接触标志，导出：

- `config/art_pass_r2_counter_motion.json`：163–174 秒，331 个采样，含末端边界。
  该文件实际被试片读取，输出使用前 330 帧。
- `config/art_pass_r2_walk_motion.json`：20–27 秒，211 个采样，**仅完成数据导出**。
  尚未配走路的换脚、遮挡与转面原画，不能当作二维走路已经完成。

[pose_edits](../../config/art_pass_r2_pose_edits.json) 在烘焙动作之后追加二维关键帧修正。
帧号相对 163 秒，单位为原画像素。`[140,-14,10]` 意为第 140 帧该关节的修正目标，
节点间按曲线过渡；改完刷新预览即可查看。预览入口 `art_pass_r2.html` 有逐帧滑杆。
二维关节落点、脚底固定点与参考姿势由人工按本镜头原画标定，三维位移经比例缩放
并限幅到每轴 38 原画像素；不是对任何图片都可自动识别骨架。

`motion_bridge_check.json` 通过：关闭二维修正会改变最终像素，移除实际非零三维头部
位移也会改变最终像素，恢复数据后图像相同。抽查固定点的原画坐标漂移为 0。
这只证明读取链与原画固定点，不能冒充鞋底和背景的物理接触验证。
首次探针选了源头部静止的蓄势帧，未产生差异；失败报告保存在
`motion_bridge_probe_a.json`。改用实测有位移的释放帧后通过，未放宽判定。
源接触标志为 `null` 时表示没有数据，不表示接触合格。

## 验证与限制

`delivery.json` 记录两个输出都为 330 帧，原音轨解码相关系数 0.999411，时偏 0 ms。
`determinism.json`：23 次反向取帧及 5 次重复取帧全部像素哈希一致。
源动作文件摘要与烘焙数据一致，世界坐标有限值检查通过。

主代理查看方式是静帧和有序帧列，包括最终 MP4 解码结果；没有声称正常速度观看。
起身过程仍只有一张中间画，受击和落地靠明确姿势与切镜衔接，尚非高密度逐帧作画。
夜刈命中前的表情变化较弱，主要靠机位与原画姿态说明紧张。装备细节在不同生成
姿势间并非逐线一致。背景和角色只覆盖当前视角，地面影为绘制近似，不能直接拿去
做大幅绕拍或走路。当前成果证明这条制作路线可以运行并改变整体画面，不宣称已
达到参考动画的完整动态质量。

## 复现

在 episode 目录启动已有静态服务，然后依次执行：

```powershell
node --import ./tools/register_loader.mjs render.mjs --serve --port 4250 --board storyboard/art_pass_r2/server
# 另一个终端；仅当原动作代码改变时重烘焙
node tools/bake_motion_to_2d.mjs
node tools/render_art_pass_r2.mjs --render
python tools/package_art_pass_r2.py
node tools/probe_art_pass_r2.mjs
```

原片和默认 viewer 未被 R2 替换。用户指出跨集收益不能留在 tools 后，本次四个工具
已改为共享 skill 的薄入口；通用执行与二维控制模块维护在
`dula-skills/draw-over-animation/scripts/` 和 `assets/motion-controls.js`。
本集 `config/art_pass_r2_pipeline.json` 保存路径、窗口、画幅和检查配置；
`art_pass_r2.js` 保留本集原画标定、镜头、五官和效果设计。

迁移后 14 个代表帧与迁移前 PNG 哈希一致；另有独立目录、不同人物键、320×180、
12fps 的 6 帧夹具走通共享工具。详情见 skill 的 `references/executable-pipeline.md`。
这证明执行部分不依赖本集的名称和时间常量，不等于第二集的艺术制作已经完成。
记录为 `shared_migration.json` 和 `portability_check.json`。迁移后整份 MP4 哈希不同，
旧完整 MP4 未另存，因此只声明 14 个无损代表帧一致，不把编码文件差异擅自归因于
元数据，也不声称全片像素逐一相同；新输出独立通过 28 次确定性检查。
